## 一、面向过程编程

#### 1.1 核心思想

**面向过程编程**：把一个需求分解成一系列要执行的步骤，然后按照步骤依次执行这些任务（关注的是**流程、步骤**）。

**示例**：建造一栋房子，需要依次完成：

1. 平整地基
2. 地基打桩
3. 地基浇筑
4. 主体施工
5. 砌墙施工
6. 外墙施工
7. 室内硬装
8. 室内软装

#### 1.2 适用场景

面向过程编程非常直接，适合**简单、线性的任务**。

#### 1.3 特点

| 特点 | 说明 |
| --- | --- |
| **优点** | 逻辑清晰、直接，适合简单任务 |
| **缺点** | 代码复用性差，维护困难，不适合大型复杂项目 |

了解了面向过程的思路后，我们自然会想：当项目变得复杂、代码需要反复复用和维护时，仅仅靠“按步骤拆分”是否够用？这正是面向对象编程要解决的问题。

### 二、面向对象编程

#### 2.1 核心思想

**面向对象编程（OOP，Object Oriented Programming）**：把事物（人/物）的特征和功能打包到一起，形成程序的基本单元——**对象**。

- **对象**可以理解为现实中具体的人/物在程序中的数字化身（万物皆对象）
- 对象包含**属性**（特征）和**方法**（功能/行为）

**示例**：

| 对象 | 属性 | 方法 |
| --- | --- | --- |
| 挖掘机 | 颜色、油耗、马力 | 推平、挖掘 |
| 混凝土搅拌车 | 容量、颜色、臂长 | 搅拌、运输、浇筑 |
| 建筑工人 | 工种、年龄、工服颜色、技能 | 打桩、砌墙、浇筑、装修 |
| 建筑材料 | 类型、数量、价格、材质 | 存储、运输、焊接、铺贴 |

#### 2.2 面向过程 vs 面向对象

| 对比项 | 面向过程 | 面向对象 |
| --- | --- | --- |
| **核心关注** | 流程、步骤 | 对象、职责 |
| **代码组织** | 按步骤拆分 | 按对象封装 |
| **适用场景** | 简单、线性的任务 | 复杂、大型的项目 |
| **复用性** | 较差 | 较好 |
| **维护性** | 较差 | 较好 |

既然面向对象强调“对象、职责”，那么对象到底从哪里来？答案就是“类”。接下来我们进入类与对象的学习，看看如何用类来批量创建结构一致的对象。

### 三、类与对象

#### 3.1 类与对象的概念

| 概念 | 说明 |
| --- | --- |
| **类（Class）** | 描述的是一组具有相同属性（特征）和方法（功能/行为）的**模板** |
| **对象（Object）** | 对象是类的实例，是基于类创建出来的（实例对象） |

> **提示**：对象是由类创建出来的，创建对象的过程也称为**对象的实例化**。一个类可以创建无数个对象。

**示例**：

- **类**：月饼模具（描述月饼的属性：颜色、形状、大小、厚度；功能：提供能量、文化传承）
- **对象**：用模具制作出来的各种月饼（五仁月饼、豆沙月饼、莲蓉月饼等）

#### 3.2 类的定义

**语法格式**：

```
# 定义类
class 类名:
    pass
创建对象
对象名 = 类名()
动态为对象添加属性
对象名.属性名1 = 属性值1
对象名.属性名2 = 属性值2
```

**示例**：

```
# 定义类
class Car:
    pass
创建对象
c1 = Car()
动态为对象添加属性（不推荐的写法，原因见下方说明）
c1.color = "red"
c1.brand = "BMW"
c1.name = "X5"
c1.price = 500000
print(c1)               # <main.Car object at 0x00000271CDE07CB0>
print(c1.brand)         # BMW
dict：以字典形式输出对象的所有属性
print(c1.dict)      # {'color': 'red', 'brand': 'BMW', 'name': 'X5', 'price': 500000}
```

> **为什么不推荐动态添加属性？**
>
> 1. **属性没有"户口"**：类本身没有声明对象应该有哪些属性，全靠调用者随手添加，看不出一个 Car 对象"应该长什么样"
> 2. **拼错不报错**：想写 `c1.brand` 时手误写成 `c1.bran = "BMW"`，程序不会报错，而是静默地多出一个错误属性，后续用 `c1.brand` 时才发现是空的（`AttributeError`）
> 3. **对象之间不一致**：A 对象有 color 属性、B 对象忘了加，程序行为难以预测
> 4. **IDE 无法提示**：编辑器不知道对象有哪些属性，没有自动补全、也查不出拼写错误
>
> 所以推荐用 3.3 的 `__init__` 初始化方法，在**类中统一定义**对象创建时的属性。

> **`print(c1)` 输出的是什么？为什么地址每次都不一样？**
>
> `<__main__.Car object at 0x00000271CDE07CB0>` 是对象默认的字符串表示：`__main__` 表示 Car 类定义在主模块中，后面是对象的**内存地址（十六进制）**。
>
> 每次运行程序时，操作系统为对象分配的内存位置不同，所以地址每次都变；同一次运行中打印同一对象，地址则不变。想让 `print` 输出可读内容，需要自定义 `__str__` 魔法方法（见第五章）。

> **说明**：类名的命名规范遵循**大驼峰命名法**（Pascal 命名法）：每个单词首字母大写、单词之间不加分隔符，如 `UserInfo`、`UserAccount`。

> **说明**：`__dict__` 是 Python 中用户自定义类实例的特殊属性，以字典形式存储对象的所有属性。

#### 3.3 定义类时指定实例属性

**语法格式**：

```
# 定义类
class 类名:
    def __init__(self, 参数列表):
        self.属性名 = 参数值
        self.属性名 = 参数值
创建对象
对象名 = 类名(参数列表)
```

**示例**：

```
# 定义类
class Car:
    def __init__(self, c_brand, c_name, c_price):
        self.brand = c_brand     # 把传入的值绑定到对象的 brand 属性上
        self.name = c_name
        self.price = c_price
创建对象：括号里的实参会自动传给 init
c1 = Car("BMW", "X5", 500000)
print(c1.dict)      # {'brand': 'BMW', 'name': 'X5', 'price': 500000}
```

> **这套代码是怎么跑起来的？（逐步拆解）**
>
> 1. 执行 `Car("BMW", "X5", 500000)` 时，Python 先在内存中创建一个空的 Car 对象
> 2. 自动调用这个对象的 `__init__` 方法，并完成参数传递：`self = 新建的空对象`、`c_brand = "BMW"`、`c_name = "X5"`、`c_price = 500000`（self 是自动传的，**不需要也不应该手动传**）
> 3. 执行 `self.brand = c_brand`：往 self 指向的对象身上挂一个 brand 属性，值是 "BMW"。三个赋值执行完，空对象就有了全部初始属性
> 4. `__init__` 执行完毕，Python 把这个初始化好的对象作为 `Car(...)` 表达式的结果返回，赋给 c1
>
> 所以 `__init__` 的作用就是"**对象出生时统一上户口**"——保证每个对象创建出来就带齐属性。

**要点**：

- `__init__`：初始化方法（魔法方法），对象创建后**自动调用**，主要用于设置对象的初始状态（设置对象属性）
- `self`：方法的第一个参数，表示**当前这个实例对象**本身

> **说明**：定义在类外面的称之为**函数**，定义在类中的函数称之为**方法**。

**小结**：

1. 定义类时，类名的命名规范？大驼峰命名法，如 `UserInfo`、`UserAccount`
2. 定义类时，`__init__` 方法的作用？`self` 参数的作用？
   - `__init__` 是初始化方法，对象创建时自动调用，主要用于设置对象的初始状态（设置对象属性）
   - `self` 是类中定义的方法的第一个参数，表示当前创建的实例对象

有了类和对象，我们还需要让对象“动起来”——也就是给对象定义行为。实例方法正是承载对象行为的关键，下面我们来看如何定义和调用实例方法。

### 四、实例方法

#### 4.1 定义实例方法

在类中定义实例方法时，语法与之前学习的函数定义方式一致，区别是**第一个参数固定为 `self`**。

**语法格式**：

```
class 类名:
    def __init__(self, 形参列表):
        self.属性名 = 参数值
        self.属性名 = 参数值
def 方法名(self, 形参列表):
    ...
def 方法名(self, 形参列表):
...
创建对象
对象名 = 类名(参数列表)
调用方法
对象名.方法名(实参)
```

**示例**：

```
class Car:
    def __init__(self, c_color, c_brand, c_name, c_price):
        """初始化方法：对象创建时自动调用，为对象设置属性"""
        self.color = c_color
        self.brand = c_brand
        self.name = c_name
        self.price = c_price
        print("初始化完毕")
# 定义实例方法：打印行驶信息
def running(self):
    print(f"{self.brand} {self.name} 正在高速行驶 ...")
定义实例方法：计算提车总价（车价 × 折扣 + 车价 × 税率）
def total_cost(self, discount=1.0, rate=0.1):
"""
根据折扣和税率计算提车总价
:param discount: 折扣系数，如 0.9 表示九折（默认 1.0 不打折）
:param rate: 税率，如 0.1 表示 10%（默认 0.1）
:return: 提车总价
"""
return self.price * discount + self.price * rate
创建对象：自动执行 init，先打印"初始化完毕"
c1 = Car("红色", "xiaomi", "x7", 17000)
调用方法：方法内通过 self 访问对象自己的属性
c1.running()                       # xiaomi x7 正在高速行驶 ...
传实参计算
t1 = c1.total_cost(0.9, 0.1)
print(t1)                          # 17000.0
设了默认参数后，不传也可以：按默认 不打折 + 10% 税率计算
t2 = c1.total_cost()
print(t2)                          # 18700.0
```

> **`self.xxx = c_xxx` 是为了什么？**
>  这不只是"为了初始化"，它实际做的是：**把调用时传进来的值，挂到对象自己身上**。`__init__` 的形参（ccolor 等）在方法执行完就销毁了，只有 `self.color` 这种绑定在对象上的属性会一直存在。所以这一步的本质是：**把"临时的参数值"变成"对象永久的数据"**。参数名加 c `前缀只是为了和属性名区分开，直接同名（`self.brand = brand）也完全合法，是更常见的写法。
>
> **方法里设置默认参数**：`def total_cost(self, discount=1.0, rate=0.1)` 与普通函数的默认参数规则一致——调用时不传就用默认值。默认参数必须放在没有默认值的参数后面。

在定义实例方法时，我们已经接触过 `__init__` 这种特殊写法。其实 Python 还提供了一整套以双下划线开头和结尾的“魔法方法”，它们会在特定时机被自动调用，让类的行为更符合直觉。

### 五、魔法方法

#### 5.1 什么是魔法方法

**魔法方法**是指 Python 中提供的以双下划线开头和结尾的特殊方法（如 `__init__`），用于定义类的特殊行为。

> **魔法方法不需要手动调用，Python 会在合适的时机自动调用。**

#### 5.2 常用魔法方法

| 魔法方法 | 描述 |
| --- | --- |
| `__init__` | 初始化方法 |
| `__str__` | 字符串表示的方法 |
| `__eq__` | 比较两个对象是否相等（equal） |
| `__lt__` | 小于（less than） |
| `__le__` | 小于等于（less than or equal） |
| `__gt__` | 大于（greater than） |
| `__ge__` | 大于等于（greater than or equal） |

#### 5.3 默认行为

```
class Car:
    def __init__(self, brand, name, price):
        self.brand = brand
        self.name = name
        self.price = price
    def running(self):
        print(f"{self.brand} {self.name} 正在高速行驶 ...")
c1 = Car("BMW", "X5", 500000)
print(c1)          # <main.Car object at 0x0000025341A26A50>
# 默认输出对象的内存地址（十六进制）
c2 = Car("BMW", "X5", 500000)
print(c2)          # <main.Car object at 0x0000025341C04A50>
print(c1 == c2)    # False（默认比较的是内存地址：两个对象地址不同）
print(c1 < c2)     # 报错 TypeError（默认不支持自定义对象之间比较大小）
```

#### 5.4 自定义魔法方法

```
class Car:
    def __init__(self, c_color, c_brand, c_name, c_price):
        self.color = c_color
        self.brand = c_brand
        self.name = c_name
        self.price = c_price
def running(self):
    print(f"{self.brand} {self.name} 正在高速行驶 ...")
def total_cost(self, discount=1.0, rate=0.1):
"""根据折扣和税率计算提车总价"""
return self.price * discount + self.price * rate
魔法方法：print(对象) 时自动调用，返回可读的字符串
def str(self):
return f"{self.color} {self.brand} {self.name} {self.price}"
魔法方法：对象 == 对象 时自动调用，按属性值判断相等
def eq(self, other):
return (self.brand == other.brand and
self.name == other.name and
self.price == other.price)
魔法方法：对象 &lt; 对象 时自动调用，按价格比较
def lt(self, other):
return self.price &lt; other.price
c1 = Car("红色", "xiaomi", "x7", 17000)
c2 = Car("红色", "xiaomi", "x7", 17000)
print(c1)          # 红色 xiaomi x7 17000（print 自动调用 str）
print(c2)          # 红色 xiaomi x7 17000
print(c1 == c2)    # True（print 时自动调用 eq，按属性值比较）
print(c1 < c2)     # False（自动调用 lt，17000 < 17000 为 False）
```

> **这段代码用来干什么？**
>
> 魔法方法就是给类的**默认行为"更改规矩"**：
>
> - 不写 `__str__`：print 出来是一串内存地址，无法被程序员理解内容；写了之后，print、f-string 输出对象时都会**自动**改用你定义的可读文本。注意它必须 `return` 字符串，而不是 print。
> - 不写 `__eq__`：`c1 == c2` 比较的是内存地址——两辆车属性全一样也是 False（世界上没有两辆完全同一辆车）；写了之后改为**按属性值**判断"业务上的相等"。
> - 不写 `__lt__`：对象之间比大小直接报 TypeError；写了之后 `c1 < c2` 自动按价格比较。排序功能 `sort()` 也会用 `__lt__`。
>
> `other` 参数：与 self 对比运算的"另一个对象"。比较类魔法方法约定返回布尔值。
>
> **常见魔法方法逐个示例**：

```
class Score:
    def __init__(self, name, value):
        self.name = name
        self.value = value
def __str__(self):                       # print / f-string 输出对象时自动调用
    return f"Score({self.name}={self.value})"
def eq(self, other):                 # a == b 时自动调用
return self.value == other.value
def lt(self, other):                 # a &lt; b 时自动调用
return self.value &lt; other.value
def le(self, other):                 # a &lt;= b 时自动调用
return self.value &lt;= other.value
def gt(self, other):                 # a &gt; b 时自动调用
return self.value &gt; other.value
def ge(self, other):                 # a &gt;= b 时自动调用
return self.value &gt;= other.value
a = Score("语文", 90)
b = Score("数学", 85)
print(a)            # Score(语文=90)          → str
print(a == b)       # False                   → eq
print(a > b)        # True                    → gt
print(a >= b)       # True                    → ge
print(a <= b)       # False                   → le
```

**小结**：

1. 什么是魔法方法？
   - Python 中提供的 `__xxx__` 形式的特殊方法
   - 魔法方法无需手动调用，Python 会在合适的时机自动调用
2. 常用的魔法方法有哪些，作用是什么？
   - `__init__`：初始化方法
   - `__str__`：字符串表示方法（print/f-string 输出对象时自动调用）
   - `__eq__`：比较两个对象是否相等（== 时自动调用）
   - `__lt__`、`__le__`、`__gt__`、`__ge__`：支持比较两个对象的大小（<、<=、>、>= 时自动调用）

前面我们反复提到“实例属性”，其实属性还有另一种形态——类属性。搞清楚两者的区别，能帮你更准确地设计对象的数据结构。

### 六、实例属性与类属性

#### 6.1 属性分类

| 类型 | 说明 |
| --- | --- |
| **实例属性** | 属于每个具体对象的属性，每个对象都独立一份（各对象特有的数据） |
| **类属性** | 属于类本身的属性，所有实例共享（所有对象共享的数据或配置） |

#### 6.2 示例

```
class Car:
    # 类属性：定义在类中、方法外（所有对象共享）
    wheels = 4
    tax_rate = 0.1
def __init__(self, c_brand, c_name, c_price):
    # 实例属性：定义在 __init__ 中、通过 self.（每个对象独立）
    self.brand = c_brand
    self.name = c_name
    self.price = c_price
def running(self):
print(f"{self.brand} {self.name} 正在高速行驶 ...")
c1 = Car("BYD", "汉", 180000)
c2 = Car("Tesla", "Model Y", 260000)
print(c1.wheels)       # 4（通过实例访问类属性）
print(c2.wheels)       # 4
print(Car.tax_rate)    # 0.1（也可以通过类名直接访问类属性）
print(c1.brand)        # BYD（访问实例属性）
print(c2.brand)        # Tesla
```

> **属性查找顺序**：通过实例对象访问属性时（如 `c1.wheel`），**先查找实例属性**（自己身上有没有）→ 实例属性不存在时，**再查找类属性**（类身上有没有）。
>
> 注意：`self.wheel = 3` 这样写在 `__init__` 里创建的是**实例属性**，它会"遮住"同名的类属性——`c1.wheel` 得到 3，但 `c2.wheel` 仍是类属性的值。一般不建议在 `__init__` 里写与类属性同名的实例属性，容易造成误解。

> - **分数校验漏了上限**：`0 <= chinese and 0 <= math and 0 <= english <= 100` 中只有英语检查了 `<= 100`，语文数学可以输入 999；三科都应写成 `0 <= x <= 100`

> **疑问解答**：
>
> - **`self.students_list = []` 为什么不直接传进来？** 系统刚创建时本来就没有任何学生数据，空列表就是这个对象的"初始状态"。学生数据是程序运行中通过"添加"功能逐步产生的。如果以后需要"带着已有数据启动"，可以把参数设计为可选：`def __init__(self, students=None): self.students_list = students if students else []`。基础版本先用空列表即可。
> - **`stu = Student(name, chinese, math, english)` 是什么语法？** 这是**类的实例化**：像调用函数一样"调用类"，Python 会创建一个 Student 对象并自动执行其 `__init__`（详见 3.3 的拆解），然后把新对象赋给 stu，最后 append 进列表保存。
> - **`print(f"当前成绩:{s}")` 为什么直接打印 s 就行？** 因为 Student 类定义了 `__str__` 魔法方法：f-string 或 print 遇到对象时会**自动调用**它的 `__str__`，把返回的字符串填进 `{}`，所以看到的不是内存地址而是格式化的成绩信息。
> - **`s.update_score(...)` —— "s 一定有这个函数吗"？** 有。`s` 的类型是 Student 类，实例自动拥有其所属类定义的所有方法。`s.update_score(90, 80, 70)` 会自动把 s 作为 self 传入，方法内部修改的就是 s 自己的属性。类的方法对每个实例都可用，这正是"对象 = 属性 + 方法"的体现。

#### 7.2 购物车管理系统

**需求**：采用面向对象的编程思想，开发一个购物车管理系统，实现商品信息的添加、修改、删除、查询功能。

**功能**：

1. 添加购物车：录入商品名称、价格、数量，保存到购物车
2. 修改购物车：输入要修改的商品名称，重新录入价格、数量后修改
3. 删除购物车：输入要删除的商品名称，根据名称删除

### 八、异常处理

#### 8.1 什么是异常

**异常**：程序运行过程中出现的错误，它会中断程序的正常执行流程。

> 补充：异常和 Bug 相关但不等同——Bug 是程序缺陷，异常是缺陷或意外输入暴露出来的"错误信号"。

**处理异常的意义**：

- 避免程序因为一个错误就整体崩溃，保证程序按预案继续执行
- 在开发阶段尽早发现、解决问题，保障程序正常执行

**常见异常类型**：

| 异常类型 | 说明 |
| --- | --- |
| `NameError` | 变量未定义 |
| `TypeError` | 类型错误 |
| `IndexError` | 索引错误 |
| `KeyError` | 字典键错误 |
| `ValueError` | 值错误（如 `int("abc")`） |
| `ZeroDivisionError` | 除数为 0 |
| `AttributeError` | 属性错误（访问对象不存在的属性） |

#### 8.2 异常处理

程序运行过程中出现异常，有两种处理方案：

| 方案 | 说明 |
| --- | --- |
| **不做处理** | 整个程序因为一个异常，中断执行 |
| **捕获异常** | 按照我们预先设计的预案处理完异常，程序继续执行 |

**语法格式**：

```
try:
    可能出现异常的业务代码1
    可能出现异常的业务代码2
    ...
except [异常类型 as 变量名]:        # 不写异常类型 = 捕获所有异常（不推荐滥用）
    出现异常时的预案
[finally:
    不管是否出现异常，都会执行的代码]
```

**示例**：

```
try:
    print("==================")
    print(my_name)                      # my_name 未定义，抛出 NameError
    print("==================")         # 异常发生后，这行不会执行
except NameError as e:
    print("程序运行报错，错误信息：", e)   # 输出：name 'my_name' is not defined
finally:
    print("释放资源 ~")
```

```
try:
    print("==================")
    print(1 / 0)                        # 抛出 ZeroDivisionError: division by zero
    print("==================")
except ZeroDivisionError as e:
    print("ZeroDivisionError", e)       # 预案处理，程序继续往下走
```

> **如果抛出的异常类型与 except 不匹配？** 比如代码里是 `1 / 0`（ZeroDivisionError），却只写了 `except NameError`——匹配不上，异常不会被捕获，继续向上传递，最终程序报错崩溃。所以 except 要写对可能的异常类型，或兜底用 `except Exception`。

**多个异常捕获**：

```
try:
    print(my_name)                      # 未定义变量 → NameError
except NameError as e:
    print("名称不存在，请检查，具体信息：", e)
except ZeroDivisionError as e:
    print("不能做被除数，请检查，具体信息：", e)
except IndexError as e:
    print("索引错误，请检查，具体信息：", e)
except Exception as e:                  # 兜底：捕获其他所有异常
    print("其他错误，请检查，具体信息：", e)
finally:
    print("无论正常执行还是出现异常，都要释放资源～")
```

> **`except:` 后面直接冒号不写类型行不行？**
>
> 行，这叫**裸 except**，会捕获所有异常（包括 `Ctrl+C` 退出等系统级异常），IDE 会给出警告提示。规范写法是 `except Exception as e:`——只捕获常规异常，范围可控、意图明确，所以**推荐始终写上 Exception**。
>
> **`finally` 是可有可无的吗？**
>
> 是的，语法上可省略。它的特点是：**无论 try 块正常执行、还是抛出异常、甚至异常类型没匹配上**，finally 里的代码都会执行，所以常用来"释放资源"（关闭文件、断开连接等）。

> **老师顺带讲的：异常的继承关系**
>
> Python 的异常也是"类"，存在继承层次：
>
> ```
> BaseException（所有异常的基类）
> └── Exception（常规异常的基类）
>     ├── NameError
>     ├── TypeError
>     ├── ValueError
>     ├── ZeroDivisionError
>     ├── IndexError
>     ├── KeyError
>     └── ... 更多具体异常
> ```
>
> 这解释了两个现象：
>
> 1. **`except Exception` 为什么能"兜底"**：子类实例也是父类类型（继承关系），NameError 等都是 Exception 的子类，所以 `except Exception` 能捕获它们——就像"异常对象的 isinstance 检查"。
> 2. **多个 except 的书写顺序**：异常从上到下依次匹配，所以**具体的异常类型写在前面，宽泛的（Exception）写在最后**；把 Exception 写在最前面，后面的分支就永远轮不到了。

**小结**：

1. 为什么要捕获异常？当程序运行出现异常，提供预案处理异常，而不是让程序中止运行
2. 如何捕获异常，具体的语法？

   ```
   try:
       可能出现异常的代码
   except 异常类型 as e:
       处理方案
   finally:
       释放资源
   ```

#### 8.3 异常传递

**异常传递**：异常在函数调用链中**层层向上上报**的过程——当前函数不处理，就传给调用它的函数；一路没人处理，最终传到主程序，程序崩溃。

**示例**：

```
def fun1():
    print("fun1 ... running ...")
    fun2()
def fun2():
print("fun2 ... running ...")
fun3()
def fun3():
print("fun3 ... running ...")
print(my_color)          # my_color 未定义，这里抛出 NameError
if name == 'main':
fun1()                   # 不捕获：异常一路传回主程序，程序崩溃
```

**在主程序统一捕获处理**：

```
def fun1():
    print("fun1 ... running ...")
    fun2()
def fun2():
print("fun2 ... running ...")
fun3()
def fun3():
print("fun3 ... running ...")
print(my_color)          # NameError 在这里产生
if name == 'main':
try:
fun1()               # 调用链最外层捕获
except NameError as e:
print("NameError", e)   # 预案处理，程序继续执行
```

**执行流程**：

```
主程序调用 fun1()
    ↓
fun1()  → 打印 "fun1 ... running ..." → 调用 fun2()
    ↓
fun2()  → 打印 "fun2 ... running ..." → 调用 fun3()
    ↓
fun3()  → 打印 "fun3 ... running ..." → print(my_color) 抛出 NameError
    ↓
fun3 不处理 → 传给 fun2 → fun2 不处理 → 传给 fun1 → fun1 不处理 → 传给主程序
    ↓
主程序的 try 捕获 NameError → 执行预案 → 程序继续
（如果一路没人捕获，程序崩溃）
```

> **为什么在主程序捕获和处理最好？**
>
> 1. **职责清晰**：fun1/fun2/fun3 只专注自己的业务逻辑，不用每个函数都包一层 try，代码干净
> 2. **统一预案**：错误提示、日志记录、资源释放集中在一处，改预案只改一个地方
> 3. **避免漏网**：调用链上任何一层抛出的异常最终都会到主程序，在出口处兜底最保险
> 4. 局部只在"知道怎么处理这个异常"的地方捕获（比如把输入错误转成重新输入），其余交给上层

**结合教务系统的升级版**：上一节 `run()` 里的 `int(input(...))`——用户输入非数字会抛 `ValueError` 中断程序。按"主程序统一捕获"的思路，把整个循环包进 try，出现输入错误就提示并继续：

```
    def run(self):
        print(f"欢迎使用教务管理系统 V{EduManagement.system_version}")
        while True:
            print()
            print("=" * 30)
            print("1.添加学生  2.修改学生  3.删除学生  4.查询指定学生  5.查询所有学生  6.退出系统")
            try:                             # 预案：处理用户输入非数字导致的 ValueError
                choice = input("选择操作:")
                match choice:
                    case "1":
                        self.add_student()   # 内部的 int(input(...)) 可能抛 ValueError
                    case "2":
                        self.update_student()
                    case "3":
                        self.delete_student()
                    case "4":
                        self.query_student()
                    case "5":
                        self.list_student()
                    case "6":
                        print("感谢使用，再见！")
                        break
                    case _:
                        print("请检查后重新输入")
            except ValueError as e:
                print(f"输入有误（{e}），请输入 0-100 之间的整数！")
            except Exception as e:           # 兜底，保证系统不因单个异常崩溃
                print(f"系统出现异常：{e}")
```
